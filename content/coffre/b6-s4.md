## Télécharger un skill ne te donne pas encore une méthode

Tu connais maintenant la logique d'ORACLE. Reste à l'avoir sur ton ordinateur. Tu peux télécharger le dossier, le ranger au hasard et continuer comme avant. Tu peux aussi lui confier tout le projet sans relire. Dans les deux cas, tu rates l'essentiel.

Le premier usage doit être petit, réel et vérifié.

## Tu vas installer, détecter et tester sans lancer le code

Le dossier contient la méthode de cadrage, de répartition, de construction et d'audit. Ton outil (Claude Code ou Codex, par exemple) doit pouvoir le retrouver quand la tâche correspond.

À la fin, tu auras le skill installé, la date de téléchargement notée dans ton projet, et un `ORSAYN-PROJECT.md` relu.

## Fais quatre gestes, dans cet ordre

1. Télécharge l'archive depuis le bouton du chapitre.
2. Décompresse-la, puis mets le dossier dans l'emplacement des skills de ton outil (pour Claude Code, `~/.claude/skills/`).
3. Vérifie que son nom apparaît dans la liste.
4. Ouvre une nouvelle conversation.

[[schema:InstallerOracleQuatreGestes]]

Ne colle pas tout le contenu dans le prompt. L'agent lit le fichier principal, puis ouvre les références utiles au moment où elles servent.

Pense à une valise bien rangée : tu n'en vides pas le contenu sur le sol pour trouver une chemise.

==Le skill reste dans son dossier. La conversation charge seulement ce dont elle a besoin.==

## Vérifie la version et l'emplacement

Demande à ton agent : « Quels skills vois-tu pour ce projet ? » Il doit répondre avec le nom détecté. Demande-lui ensuite de noter dans le projet la date du téléchargement : c'est ta référence de version.

[[maquette:EcranInstallationOracle]]

Le chemin exact dépend de ton outil : lis sa documentation ou sa liste de skills au lieu de deviner.

Si le nom n'apparaît pas, ne poursuis pas comme si tout fonctionnait. Corrige l'emplacement, ou relance la détection prévue par l'outil.

:::retiens
Une installation réussie se constate dans la liste. Elle ne se déduit pas du simple déplacement d'un dossier.
:::

## Lance seulement le cadrage

Choisis un vrai projet assez petit. Donne la scène métier, les sources autorisées et les contraintes déjà connues.

Demande le premier dossier projet. Puis arrête-toi avant l'architecture et le code.

[[schema:PremierCadrageSeulement]]

Relis chaque ligne. Une sortie bien présentée peut cacher une hypothèse que personne n'a confirmée.

Marque chaque ligne : confirmée, à vérifier ou inconnue. Ajoute le nom de la personne qui peut répondre.

## Un projet corrige d'abord son propre dossier

Le skill peut te proposer une application partagée alors que ton client exige une copie séparée. Cette décision appartient d'abord au projet : tu corriges `ORSAYN-PROJECT.md`, pas le skill.

[[schema:UneErreurNeDevientPasUneRegle]]

Une erreur qui revient et que tu sais reproduire peut justifier un nouveau contrôle. Une réussite répétée peut proposer une nouvelle règle, après comparaison.

Un seul cas ne suffit pas. Sinon, chaque client transforme la méthode entière selon sa préférence.

==Le projet apprend tout de suite. Le skill apprend seulement quand la règle tient ailleurs.==

## Relis le dossier comme une personne extérieure

Une bonne relecture ne demande pas si le texte est propre. Elle cherche ce qui manque pour décider.

[[maquette:ReadbackOracleProject]]

Dans la maquette, chaque ligne dit son état : « Confirmé », « À vérifier », « Inconnu », « Hors projet ». Une ligne nomme qui répond, une autre la prochaine action. Aucune action externe ne doit partir pendant ce premier essai.

## Prends Yacine, pâtissier à Rouen

:::exemple Yacine teste le cadrage avant l'application
Yacine veut un carnet de commandes pour ses gâteaux. Il reçoit aujourd'hui les demandes par téléphone et par Instagram.

Le premier cadrage propose une application partagée. Yacine précise qu'il sera seul à l'utiliser. Ses clients continueront de remplir un formulaire simple.

Il corrige donc le mode du produit dans son dossier. Il note aussi que la date de retrait et les allergies doivent rester visibles.

Il n'a encore créé aucun écran. Pourtant, il vient d'éviter des comptes clients inutiles et une mauvaise architecture.
:::

## À toi de jouer

Compte une heure aujourd'hui.

1. Télécharge le dossier et range-le dans les skills de ton outil.
2. Demande la liste des skills et vérifie que le nom apparaît.
3. Note la date du téléchargement dans ton projet.
4. Produis uniquement le premier cadrage, puis relis-le ligne par ligne.

À la fin, tu as une installation constatée et un dossier projet corrigé.

## Version pour ton IA

```text
Utilise la version installée du skill pour cadrer ce projet.

Commence par trois questions maximum.
Cite les fichiers de contexte que tu lis.

Pour cette première session, produis seulement :
1. la scène principale ;
2. le résultat attendu ;
3. le mode du produit à confirmer ;
4. les données utilisées ;
5. ce qui reste hors du projet ;
6. les décisions prises ;
7. les réponses inconnues ;
8. les prochains contrôles.

Arrête-toi avant l'architecture, le code et toute action externe.
```
