Tu ouvres ton éditeur de code avec une idée simple : « Je vais faire un site pour mon artisan. » Dix minutes plus tard, l'IA te demande quelle stack utiliser. Tu cites un nom connu. Elle invente le reste : le titre, les sections, même les chantiers que l'artisan accepte.

Le problème ne vient pas du code. Il vient des décisions que personne n'a prises avant de le lancer.

## Un framework ne donne pas une direction

Un framework, c'est le cadre technique qui fait tenir ton site : comment les pages s'affichent, comment les données circulent. Il arrive après le besoin, le message et le dessin de la page, jamais avant. Un excellent framework peut construire très proprement le mauvais site.

Tu écris d'abord un brief court d'une page. Ensuite, tu relies le message, la structure et le style pour que la page raconte une seule histoire. Enfin, tu choisis la technique la plus simple qui couvre le projet.

À la fin, tu as quatre documents :

- un brief qu'une autre personne peut comprendre sans toi ;
- une carte de page avec un rôle pour chaque section ;
- une direction visuelle commentée ;
- une fiche technique avec un choix et sa raison.

==Le framework sert le projet. Il ne décide jamais du projet.==

On commence par ce qui évite le plus de retours en arrière : le bon ordre avant de construire.
